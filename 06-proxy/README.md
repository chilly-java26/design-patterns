# 代理模式 (Proxy Pattern)

## 定义
代理模式为其他对象提供一个代理，以控制对这个对象的访问。代理对象在客户端和目标对象之间起到中介作用。

## 核心概念

### 角色组成
- **抽象主题（Subject）**：定义代理和真实对象的共同接口
- **真实主题（RealSubject）**：真正的业务对象
- **代理（Proxy）**：持有真实对象的引用，控制对它的访问

### 工作原理
```
客户端 → 代理对象 → 真实对象
```
客户端通过代理访问真实对象，代理可以在调用前后添加额外的逻辑。

## 静态代理 vs 动态代理

### 静态代理
- **定义**：在编译期就确定代理类，需要手动编写代理类代码
- **本项目的 Main.java 示例就是静态代理**

### 动态代理
- **定义**：在运行时动态生成代理类，使用反射机制
- **JDK 动态代理**：基于接口，使用 `Proxy` 和 `InvocationHandler`
- **CGLIB 动态代理**：基于继承，可以代理没有接口的类

### 对比表格

| 特性 | 静态代理 | 动态代理 |
|------|---------|---------|
| **代理类生成** | 编译期手动编写 | 运行时自动生成 |
| **代理类数量** | 一个接口一个代理类 | 一个Handler处理多个类 |
| **灵活性** | 低 | 高 |
| **代码量** | 多（每个类都要写代理） | 少（通用Handler） |
| **性能** | 略快 | 略慢（反射调用） |
| **使用场景** | 代理类少且固定 | 需要代理多个类 |

### JDK 动态代理 vs CGLIB 动态代理

| 特性 | JDK动态代理 | CGLIB代理 |
|------|------------|----------|
| **实现方式** | 基于接口（实现接口） | 基于继承（生成子类） |
| **是否需要接口** | 必须有接口 | 不需要接口 |
| **final类/方法** | 不受限制 | 不能代理 |
| **性能** | 略快 | 略慢 |
| **JDK依赖** | JDK自带 | 需要第三方库 |
| **使用场景** | 目标对象有接口 | 目标对象无接口 |

## 代理模式的类型（按功能分类）

### 1. 虚拟代理（Virtual Proxy）
- **作用**：延迟加载，只在真正需要时才创建真实对象
- **场景**：加载大对象（图片、视频、大文件）
- **本项目的 Main.java 就是虚拟代理**

### 2. 保护代理（Protection Proxy）
- **作用**：控制访问权限
- **场景**：权限验证、访问控制

### 3. 远程代理（Remote Proxy）
- **作用**：为远程对象提供本地代理
- **场景**：RMI、Web Service

### 4. 缓存代理（Cache Proxy）
- **作用**：缓存结果，避免重复计算
- **场景**：数据库查询缓存、计算结果缓存

## 使用场景
- 延迟加载：对象创建成本高，希望延迟到真正需要时再创建
- 访问控制：需要控制对对象的访问权限
- 日志记录：需要记录方法调用信息
- 缓存代理：缓存昂贵操作的结果
- 远程代理：访问远程对象

## 优缺点

### 优点
- ✅ 职责清晰：真实对象只关注业务逻辑
- ✅ 扩展性好：可以在不修改真实对象的情况下添加功能
- ✅ 延迟加载：节省资源，提高性能
- ✅ 保护真实对象：控制访问权限

### 缺点
- ❌ 增加复杂度：多了一层代理
- ❌ 可能降低性能：增加了间接调用

## 示例说明

### 场景：图片浏览器
用户打开一个文件夹，里面有很多图片：
- **不使用代理**：一次性加载所有图片 → 慢，占内存
- **使用代理**：只加载用户查看的图片 → 快，省内存

### 代码结构

#### 静态代理示例
- `Image.java` - 抽象主题接口
- `RealImage.java` - 真实图片对象（加载耗时）
- `ImageProxy.java` - 图片代理（延迟加载）
- `Main.java` - 静态代理演示

#### 动态代理示例
- `DynamicProxyDemo.java` - JDK 动态代理演示
- `StaticVsDynamicDemo.java` - 静态代理 vs 动态代理对比
- `CglibProxyDemo.java` - CGLIB 动态代理说明

### 关键点
1. **延迟加载**：代理对象创建时不加载真实图片
2. **透明性**：客户端通过接口使用，不知道是代理还是真实对象
3. **缓存效果**：真实对象创建后被缓存，再次调用不重新加载

```bash
# 静态 vs 动态代理对比
mvn exec:java -Dexec.mainClass="com.designpatterns.proxy.StaticVsDynamicDemo"

# CGLIB 动态代理说明
mvn exec:java -Dexec.mainClass="com.designpatterns.proxy.CglibProxyDemo"
```

## 与其他模式的区别

### 代理 vs 装饰器
- **代理**：控制访问，可能延迟创建
- **装饰器**：增强功能，对象已存在

### 代理 vs 适配器
- **代理**：接口相同，控制访问
- **适配器**：接口不同，转换接口

## 实际应用
- **Spring AOP**：动态代理实现切面
- **Hibernate/MyBatis**：懒加载代理
- **RPC框架**：远程服务代理
- **图片加载库**：虚拟代理延迟加载

# 策略模式 UML 类图

## 标准策略模式结构

```
┌─────────────────────────┐
│      Context            │
│  (ShoppingCart)         │
├─────────────────────────┤
│ - strategy: Strategy    │◆───────────┐
├─────────────────────────┤            │
│ + setStrategy(Strategy) │            │ 持有引用
│ + checkout(amount)      │            │
└─────────────────────────┘            │
                                       │
                                       ▼
                        ┌──────────────────────────┐
                        │   <<interface>>          │
                        │   PaymentStrategy        │
                        ├──────────────────────────┤
                        │ + pay(amount): void      │
                        └──────────────────────────┘
                                     △
                                     │ 实现
                 ┌───────────────────┼───────────────────┐
                 │                   │                   │
    ┌────────────────────┐  ┌───────────────┐  ┌───────────────┐
    │ CreditCardPayment  │  │ AlipayPayment │  │ WeChatPayment │
    ├────────────────────┤  ├───────────────┤  ├───────────────┤
    │ - cardNumber       │  │ - email       │  │ - openId      │
    │ - cvv              │  ├───────────────┤  ├───────────────┤
    ├────────────────────┤  │ + pay()       │  │ + pay()       │
    │ + pay()            │  └───────────────┘  └───────────────┘
    │ - maskCardNumber() │
    └────────────────────┘
```

## 符号说明

| 符号 | 含义 |
|------|------|
| `◆──` | 组合关系（Composition）：整体包含部分 |
| `△` | 继承/实现关系：子类实现父类 |
| `<<interface>>` | 接口 |

## 核心关系

### 1. Context 持有 Strategy 引用

```java
public class ShoppingCart {
    private PaymentStrategy strategy;  // 持有策略引用
}
```

**特点：**
- Context 通过策略接口调用算法
- 可以在运行时动态切换策略
- 降低耦合，符合依赖倒置原则

### 2. 具体策略实现策略接口

```java
public class CreditCardPayment implements PaymentStrategy {
    @Override
    public void pay(double amount) {
        // 具体实现
    }
}
```

**特点：**
- 每个具体策略封装一种算法
- 策略之间可以互相替换
- 符合开闭原则（对扩展开放，对修改关闭）

## 对比：使用策略模式前后

### ❌ 不使用策略模式

```
┌──────────────────────┐
│  PaymentProcessor    │
├──────────────────────┤
│ + processPayment()   │
│   {                  │
│     if (信用卡) {    │
│       // 信用卡逻辑  │
│     } else if (支付宝) {
│       // 支付宝逻辑  │
│     } else if (微信) {
│       // 微信逻辑    │
│     }                │
│   }                  │
└──────────────────────┘
```

**问题：**
- 所有逻辑耦合在一起
- 添加新支付方式需要修改类
- 违反开闭原则
- 难以测试和维护

### ✅ 使用策略模式

```
         Strategy Interface
                △
         ┌──────┼──────┐
    Strategy1 Strategy2 Strategy3
      (独立)    (独立)    (独立)
```

**优势：**
- 策略独立，易于维护
- 添加新策略不修改现有代码
- 符合开闭原则
- 易于测试

## 实际项目中的应用

### Spring 框架中的策略模式

```
┌──────────────────────┐
│   ResourceLoader     │
├──────────────────────┤
│ + getResource()      │
└──────────────────────┘
           △
           │
    ┌──────┴──────────────────┐
    │                          │
┌──────────────┐    ┌──────────────────┐
│ ClassPath    │    │ FileSystem       │
│ Resource     │    │ Resource         │
└──────────────┘    └──────────────────┘
```

**说明：** Spring 使用策略模式处理不同来源的资源加载。

### Java 集合框架

```
Collections.sort(list, new Comparator<>() {
    // 自定义排序策略
});
```

**说明：** `Comparator` 就是一个策略接口，允许不同的排序算法。

## 设计原则体现

| 原则 | 如何体现 |
|------|---------|
| **开闭原则** | 新增策略不需修改现有代码 |
| **单一职责** | 每个策略类只负责一种算法 |
| **依赖倒置** | Context依赖抽象接口，不依赖具体实现 |
| **里氏替换** | 所有策略对象可以互相替换 |
| **接口隔离** | 策略接口简洁，只定义必要方法 |

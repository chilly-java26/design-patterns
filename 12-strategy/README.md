# 策略模式 (Strategy Pattern)

## 一句话本质
**将算法封装成独立的策略类，让它们可以互相替换，使算法的变化独立于使用算法的客户端。**

## 核心思想
不同的做事方式（策略）可以随时切换，而不影响使用者的代码。

## 模式结构

```
┌─────────────────┐
│ ShoppingCart    │  (上下文)
│ - strategy      │◆────────┐
│ + setStrategy() │         │
│ + checkout()    │         │
└─────────────────┘         │
                            │
                            ▼
              ┌──────────────────────┐
              │ PaymentStrategy      │  (策略接口)
              │ + pay(amount)        │
              └──────────────────────┘
                         △
         ┌───────────────┼───────────────┐
         │               │               │
┌────────────────┐ ┌─────────────┐ ┌─────────────┐
│ CreditCard     │ │ Alipay      │ │ WeChat      │ (具体策略)
│ Payment        │ │ Payment     │ │ Payment     │
└────────────────┘ └─────────────┘ └─────────────┘
```

## 角色说明

1. **Strategy（策略接口）**：`PaymentStrategy`
   - 定义所有策略的统一接口

2. **ConcreteStrategy（具体策略）**：`CreditCardPayment`, `AlipayPayment`, `WeChatPayment`
   - 实现具体的算法逻辑

3. **Context（上下文）**：`ShoppingCart`
   - 持有策略对象的引用
   - 可以在运行时切换策略

## 使用场景

1. **多种算法可选**：当一个系统有多种算法可供选择时
2. **避免复杂条件判断**：替代大量的 if-else 或 switch-case
3. **算法独立变化**：算法的变化不影响客户端代码
4. **运行时切换**：需要在运行时动态选择算法

## 实际应用例子

- **支付方式选择**：信用卡、支付宝、微信支付（本例）
- **排序算法**：快速排序、归并排序、冒泡排序
- **压缩算法**：ZIP、RAR、7Z
- **路由算法**：最短路径、最快路径、最省钱路径
- **数据验证**：邮箱验证、手机号验证、身份证验证
- **价格计算**：普通用户、VIP用户、超级VIP用户的折扣策略

## 优点

✅ **开闭原则**：新增策略不需要修改现有代码  
✅ **单一职责**：每个策略类只负责一种算法  
✅ **消除条件语句**：避免复杂的 if-else 判断  
✅ **运行时切换**：可以动态改变对象的行为  
✅ **易于测试**：每个策略可以独立测试

## 缺点

❌ **类数量增加**：每个策略都是一个类  
❌ **客户端需了解策略**：客户端需要知道不同策略的区别  
❌ **策略对象增多**：可能会创建很多策略对象

## 与其他模式的区别

### 策略模式 vs 状态模式
- **策略模式**：客户端主动选择策略，策略之间互相独立
- **状态模式**：状态内部自动切换，状态之间有依赖关系

### 策略模式 vs 工厂模式
- **策略模式**：关注算法的替换和切换
- **工厂模式**：关注对象的创建

## 运行示例

```bash
cd 12-strategy
mvn clean compile
mvn exec:java -Dexec.mainClass="com.designpatterns.strategy.Main"
```
